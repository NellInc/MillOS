# MillOS Exhaustive Improvement Programme, Second Pass

## Goal

Reassess the completed exhaustive candidate rather than merely repeating its checks. Find and implement every remaining safe, coherent, locally actionable improvement across product behavior, architecture, correctness, security, privacy, industrial boundaries, performance, accessibility, UX, visual quality, audio behavior, testing, CI and deployment, dependencies, assets, rights metadata, documentation, repository hygiene, operations, and maintainability. Preserve the isolated candidate and unrelated work. Prove the exact result at every locally available layer, while keeping machine evidence separate from human, device, rights, plant, publication, and external-capacity authority.

This pass extends the first programme in `_contprompts/millos_exhaustive_improvements_2026-08-12.md`. The earlier ledger remains the full inventory of completed work and long-range opportunities. This document records newly discovered residual defects, promotes newly actionable backlog items, and defines the second-pass acceptance contract.

## Adversarial pre-check

1. **Scope:** the request is intentionally repository-wide. The implementation boundary remains finite: safe local changes with testable acceptance criteria. Major rendering refactors, physical-plant authorization, rights clearance, human taste, and publication remain separate programmes or authorities.
2. **Candidate:** all edits belong in `/Users/nellwatson/Documents/GitHub/MillOS-codex-exhaustive-improvements` on `codex/exhaustive-improvements`. The dirty main checkout remains untouched.
3. **Old contracts:** credential, WebSocket, persistence, model, deployment, and runtime changes must identify old clients or stored data that still speak the previous contract. Compatibility is preserved where it does not perpetuate a material leak. Explicitly deprecated credential paths may be removed because the maintained browser client and manifests already use their replacements.
4. **Evidence:** source inspection, tests, builds, browser runs, native captures, infrastructure rendering, and external acceptance are different evidence classes. One never substitutes for another.
5. **Resource ownership:** no foreign browser, server, or test process may be killed or commandeered. Runtime and performance work waits for an owned port and a resource-stable host.
6. **Security review limitation:** the managed standard security scan failed before returning a scan identifier or workspace. Manual source-backed review continues, but it does not claim independent managed-scan coverage.

Tests added in this pass therefore target trust boundaries and migrations rather than inflating a global percentage with low-value lines.

6. The main checkout's unrelated files remain untouched.
7. Human, device, rights, industrial, external-operations, and publication decisions remain visible and unclaimed.
